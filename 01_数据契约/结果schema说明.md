| 字段 | 类型 | 单位 | 含义 |

## 2 timeseries（逐时段序列，画图用）

★★ **三个最容易踩的索引约定，务必注意**：

| # | 约定 | 说明 |
|---|---|---|
| 1 | **`t` 从 1 开始** | `timeseries.a[rid][t-1]` 对应第 t 步（不是 t） |
| 2 | **区段键是字符串** | `F` / `g1` / `g2` / `q_hat` 的键是 `"1"`..`"17"`（JSON 不允许数字键），区段编号从 **1** 开始 |
| 3 | **`s` 是按车场索引的字典** | 与 `x`/`u`/`b` 一致；不是列表 |

| 字段 | 结构 | 单位 | 含义 |
|---|---|---|---|
| `t` | `[T]` int | — | 时段序号 1..T（T=16 对应 06:00–10:00，Δ=15 min） |
| `a` | `{rid: [T]}` int | 列 | 各交路在线车底数 |
| `a_total` | `[T]` int | 列 | Σ 各交路 |
| `x` | `{did: [T]}` int | 列 | 唤醒数 |
| `u` | `{did: [T]}` int | 列 | 上线数 |
| `b` | `{did: [T]}` int | 列 | 待班数（已唤醒、可立即上线） |
| `s` | `{did: [T]}` int | 列 | 回段数 |
| `w` | `{rid: [T]}` 0/1 | — | 开行状态（1=开行） |
| `z` | `[T]` 0/1 | — | 结构变更指示（★ 无成本松弛，展示时建议改用 `w` 差分） |
| `F` | `{"m": [T]}` float | **列/h** | 区段列车流（通过能力约束对象） |
| `g1` | `{"m": [T]}` float | **人/h** | 超**定员**（ρ₁=1.0）的缺口 |
| `g2` | `{"m": [T]}` float | **人/h** | 超**最大载客**（ρ₂=1.394）的缺口 |
| `q_hat` | `{"m": [T]}` float | **人/h** | 预测断面客流 |

> `rid` = 交路 id 列表（如 `["r0","r1","r2"]`）
> `did` = 车场 id 列表（如 `["D1","D2"]`）

## 3 时段 → 时刻的换算

```js
// Δ = 15 min，起点 06:00
function timeLabel(t) {           // t 从 1 开始
  const m = (t - 1) * 15 + 6 * 60;
  return String(Math.floor(m / 60)).padStart(2,'0') + ':' +
         String(m % 60).padStart(2,'0');
}
// t=1 → "06:00"   t=16 → "09:45"
```

## 4 cost_terms（各成本项原始量）

`wait_raw` / `crowd1_raw` / `crowd2_raw` / `km_raw` / `hold_raw`

**注意**：这些是**原始量**，量纲各不相同。
`objective` 是它们各自**除以自己的归一化基准再加权**的和，
所以 **`cost_terms` 的各项之间不能直接比较大小**。

## 5 params_used（本次实际生效的参数）

★ **界面上应把它显示出来**——结果必须可复现、可追溯。

| 字段 | 含义 |
|---|---|
| `tau_steps` | `{did: int}` 本次实际生效的出库提前期（步） |
| `u_max_tph` | `{did: float}` 出入段能力（列/h） |
| 其余 | 权重、决策周期、时域长度、目标计划等 |

## 6 单位约定（做图时最容易错的地方）

| 量 | 单位 | 说明 |
|---|---|---|
| 断面客流 `q_hat` | **人/h** | 不是人/步 |
| 区段列车流 `F` | **列/h** | 不是列/步 |
| 拥挤缺口 `g1`/`g2` | **人/h** | |
| 等待成本 `wait_raw` | 人·h | |
| 车公里 `km_raw` | 列·km | |
| 待班 `hold_raw` | 列·步 | |
